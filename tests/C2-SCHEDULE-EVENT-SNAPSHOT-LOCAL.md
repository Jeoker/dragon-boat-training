# C2.4 排期事件快照：本地前置切片

日期：2026-09-27。此切片只改变本地 C1 排期事务内新建的 `SCHEDULE_CHANGED` outbox 内容；未部署 Worker、Apps Script 或 Pages，未向 Google 写入 `ScheduleTemplates`、`TrainingWeeks` 或 `Practices`。独立 `c2test` 仍只运行已验收的成员／赛季名单版本导出。

一次排期操作可能改变多个目标行。准备一周会建立周次和多场草稿训练；开放一周会同时发布全部未取消的训练；替换默认模板会停用旧模板并建立新模板。若十分钟后只凭事件 ID 读取 Cloudflare 当前行，较晚改期、取消或再次替换模板会覆盖先前事件的内容。

现在七条排期写入路径在各自 SQLite 事务内捕获 `snapshot_schema=1`、当时的 `season_version`，以及本次改变的完整模板、周次和训练源行。行从已持久写入的 SQLite 表读取，并按稳定 ID 排序。模板替换捕获本次停用和新增的模板；准备周次捕获新周及生成的全部训练；立即开放或定时开放时捕获更新后的周次和实际发布的训练。未来才开放的周次在“确认”事件中只有周次变化、训练数组为空；到期发布事件再捕获训练变化。新增、单场发布、改期、取消各捕获该场训练及周次。取消的训练保留在内部 outbox 中作为 Google 行墓碑，公开排期仍不显示它，也不把它归档为历史训练。

连续准备、开放、新增、发布、改期、取消、替换模板的回归检查了八条事件各自的旧值和版本。定时开放测试另验证确认事件与真正到期发布事件的区别。验证：`npm test` 192／192、`npm run cf:test` 104／104、`npm run cf:check` 通过。Wrangler 在此 Windows 沙箱仍打印日志目录 EPERM 及故障注入 alarm 文本，但测试退出码为 0。

这些是**固定的 Cloudflare 源快照**，不是 Google 的目标补丁或回执。后续导出器须拒绝没有完整快照的旧排期事件，除非通过专门核验迁移；不得从当前行猜测旧事件。导出需先确认同绑定版本的赛季、教练和模板等引用，再按事件顺序对 Google 三张排期表做有界补丁、写后核验及回执，且只有整条事件所有目标都核验成功后才能确认 outbox。报名导出还须先确认其训练和成员已存在于 Google。真实部分写入、响应丢失和关联报名／座位批次尚未验收；周期调度属 C2.5。
