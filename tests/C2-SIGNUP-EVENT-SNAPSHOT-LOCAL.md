# C2.4 报名事件快照：本地前置切片

日期：2026-09-27。此切片**只改变本地 C1 报名事务写入的 outbox 内容**；未部署 Worker、Apps Script 或 Pages，尚未向 Google `SignupsCurrent` 写入报名。独立 `c2test` 继续运行上次已验收的成员／赛季名单版本导出。

一次报名、换侧或取消可能同时改变发起人的状态、递补队员的状态及私有／已发布座位。十分钟后若只读取 Cloudflare 当前行，较晚操作会覆盖较早事件所代表的状态。现在每条新 `SIGNUPS_CHANGED` 事件在原报名事务中捕获 `snapshot_schema=1`、当时的 `practice_version` 和 `signup_version`，以及**当次实际变化的所有报名行**（含自动递补，按成员 ID 稳定排序）。每行包含稳定三元 ID、偏好、状态、原报名时间及序号、更新时间和请求 ID。原有发起人、递补 ID 及座位版本字段仍保留；若报名触发排座调整，额外记录私有草稿／正式版是否改变。无变化的同偏好更新仍不产生新事件。

回归场景在 Google 尚未导出的情况下连续执行左侧报名、另一人左侧候补、首人换到右侧、取消及重新报名。五个 outbox 分别保留报名版本 1–5；第一条仍是首人的左侧状态，第三条同时包含首人右侧与候补递补后的左侧状态，第四条保留取消，第五条重新报名的排队序号从 1 变成 3，而数据库最新行已是重新报名后的状态。此测试验证了较晚修改不会重写早期事件的固定输入，不证明 Google 写回成功。

验证：`npm test` 192／192、`npm run cf:test` 101／101、`npm run cf:check` 通过。Wrangler 仍会打印本机日志目录 EPERM 与故障注入用例的 alarm 异常文本，测试进程退出码为 0；这些输出不等于远端负载或 Google 链路验收。

接下来的导出器必须拒绝没有 `snapshot_schema=1` 的旧报名事件，除非经过可核验的专门迁移；不得从当前行推测旧事件目标。写入前还须核验同绑定版本的成员与训练行、该事件前的报名 B/G 和连续 `signup_version`，逐个保存固定目标及回执；Google 多 Tab 不具备原子事务，**只有当次报名行和其引起的座位变化均核验后**才能确认原事件。座位变更目前只保存版本与变更标志，尚未捕获完整当时座位，因此带排座影响的事件仍不能进入导出。`SignupsCurrent` 本身没有 `signup_version` 列；版本由 outbox 与 Cloudflare B／批次元数据跟踪，不应假称可在 Google 报名行直接读到该版本。真实部分写入及响应丢失、旧事件接续、训练／排座关联批次都留待后续切片。
