# C1.2 排期验收

> 状态：2026-09-21，本地实现与验证完成；未部署 staging，未连接 Pages 或 Google 业务同步，生产仍由 Apps Script／Sheets 负责。

## 实现边界

- SQLite schema v3 在 v2 之上增加模板、训练周、训练场次、报名／排座版本占位和排期影子快照表；v1–v2 数据原地保留。
- 排期 API 使用独立 DTO 和严格运行时解析，统一复用 C1 会话、请求身份、不可变回执、审计和 outbox。正常写入返回原操作结果及可选最新管理视图，视图不写入不可变回执。
- 有效模板生成私有周草稿；同一周的新请求返回现有权威周，不重新生成已被修改或取消的场次。
- 整周可以立即开放或预约开放。预约确认与持久任务原子提交；任务核对后端代次、写入 epoch、赛季、周和确认版本。后续编辑会使旧任务成为无操作。
- 开放周新增场次必须单独发布。改期使用版本绑定预览，可跨日历周但保留原 publication week；取消只保留私有操作墓碑，公开排期与以后历史均不包含该场次。
- 排期影子导入保留稳定 ID、版本和 generation key，拒绝版本倒退、同版本漂移、来源身份换绑、悬空引用及不一致发布／取消状态。省略行不是删除；导入不产生 Google outbox，也不启动预约任务。

## 本地证据

Cloudflare Workers／Durable Object 官方本地运行时验证：

- schema v2 → v3 保留核心赛季并创建空排期表；未来或损坏版本继续拒绝。
- 纽约时区不存在及重复的夏令时当地时间均拒绝；周起点、赛季边界、训练先后和两小时前报名截止由服务器计算。
- 周草稿和开放周新增场次在发布前不进入公开投影；立即开放整周原子发布。
- 预约任务到期发布一次，重放不重复操作；预约后修改使旧任务安全完成为无操作。
- 修改预览绑定赛季、周、训练及报名版本；未预览的字段改变拒绝。跨周改期保持原周，取消墓碑只在管理视图可见。
- 排期快照幂等、来源快照漂移和版本倒退拒绝；导入的预约周没有持久任务。
- C1 所有十九个动作的方法、业务权限和接口清单保持一致，production 入口继续固定隐藏。

验收时 Cloudflare 测试 **33／33**、项目 Node 测试 **180／180**；Cloudflare 类型检查和 dry-run、Astro 检查与三个页面构建、Apps Script 业务及独立桥接构建均通过。
