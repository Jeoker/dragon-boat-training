# C1.5 冻结历史与运维验收

> 状态：2026-09-21，本地实现、代码审查与验证完成；未部署本轮 staging，未连接 Pages 或 Google 业务同步，生产仍由 Apps Script／Sheets 负责。

## 实现边界

- SQLite schema v6 在 v5 之上增加不可变训练历史、追加式历史说明、赛季荣誉墙索引、历史影子快照、应用用量、分块备份，并为按赛季审计和待冻结训练增加索引；v1–v5 数据原地保留。
- `shared/c1-history-contract.ts` 定义历史导入、管理读取、更正、审计和备份 DTO 与严格运行时解析；[C1 接口清单](../contracts/api-cloudflare-c1.json)记录十一个新增动作，当前共四十二个动作。
- 已发布且未取消的训练在 `end_at + 24h` 后冻结。最新正式 revision 的显示姓名、Coach、Steerer 和船位进入不可变快照；没有正式 revision 的已发布训练保存为 `UNPUBLISHED`。成员之后改名不会改变已冻结荣誉墙。
- 取消训练完全排除，不产生训练历史，也不计入整季归档。赛季截止后先转为 `COMPLETED`；全部有效训练冻结后建立赛季索引并转为 `ARCHIVED`。公开赛季目录、赛季训练及管理审计均使用稳定 keyset cursor。
- 历史更正只追加单行说明并递增 `history_version`，不改写最终座位快照。写入继续把业务结果、不可变请求回执、审计及 `HISTORY_CHANGED` outbox 放在同一 SQLite 事务中。
- 历史影子导入要求核心赛季已经是 `ARCHIVED`，重新核对训练、最终 revision、姓名／座位、连续更正版本及现有不可变内容；省略记录不视为删除，导入不产生 Google outbox。
- 自动维护只在 `writer_epoch > 0` 或内部 `history_maintenance_enabled=true` 时启用。当前 staging 配置仍是影子代次 `0`，导入不会自行完成或归档赛季；C4 才正式取得写入权。专项测试直接设置内部开关，只用于验证任务行为。
- 备份在单个 SQLite 事务内截取业务、请求结果、审计、outbox、任务和迁移状态，按一百行分块。每块与 manifest 分别计算 SHA-256，校验时还会把实时分块描述与 manifest 逐项交叉核对。`coach_sessions`、公开限流状态和备份自身表属于短期或递归状态，不进入导出。
- `get-operations` 返回数据库大小、实时行数和最近三十个每日应用快照。后台每小时最多重算一次用量，待冻结扫描只读取未取消且尚未冻结的公开训练；这些值不能替代 Cloudflare 账单或平台配额。

## 代码审查修正

1. 自动维护最初会在 `writer_epoch=0` 的历史影子导入后运行，可能把尚未取得写入权的数据继续推进。现在通过写入代次和内部开关双重隔离，专项测试覆盖“可导入、无任务”。
2. 待冻结修复最初每次写入都会扫描所有已发布训练并重复处理已冻结／已取消记录。现在只扫描未取消且缺少历史快照的训练，并使用部分索引；待执行任务的到期时间可随训练时间修改。
3. 应用用量最初在每次写操作后执行多次全表计数。现在同一日期每小时最多采集一次，运维读取仍返回实时总数。
4. 备份校验最初没有把分块表中重算的摘要重新连回 manifest。现在同时检查分块内容、分块摘要、manifest 分块描述、数量字段和 manifest 总摘要；故障注入覆盖“内容与分块摘要同时篡改”。
5. 历史写入口和 `get-operations` 的读写声明已经分开，纯读取不触发维护写入。任务失败不会在平台默认重试次数后永久放弃，修复来源数据后仍可在后续 alarm 恢复。

## 本地证据

Cloudflare Workers／Durable Object 官方本地运行时验证：

- schema v5 → v6 保留原表，补齐审计季节字段、索引和全部历史／备份表。
- 两场有效训练分别冻结为 `FROZEN` 与 `UNPUBLISHED`，取消训练不出现；三页 keyset 分页合并后无重复或漏项。
- 冻结姓名在成员改名后保持不变；公开响应不含成员 ID、草稿或报名历史。
- 历史说明支持幂等重放，拒绝多行文本、同编号换参数和旧版本；按赛季审计分页稳定。
- 冻结任务在第七次失败后没有永久放弃；修复缺失姓名后第八次成功，整季随后归档。
- 受保护备份能读取分块、核对正确／错误 manifest 摘要，并拒绝经过双重篡改的分块；运维接口返回 schema、存储和实时数量。
- `writer_epoch=0` 的完整历史影子导入可幂等重放、拒绝漂移，并且不会创建冻结或赛季任务。

验收时 Cloudflare 测试 **65／65**，其中 C1.5 专项 **6／6**；项目 Node 测试 **184／184**。Cloudflare 类型检查、类型生成和 dry-run、Astro 检查与三个页面构建、Apps Script 业务及独立桥接构建均通过。JSON 清单可解析，Git whitespace 检查通过。

## 尚未完成

C1.6 仍需用完整迁移样本做跨域回归，并部署隔离 staging 验证真实远端 Durable Object 重启、任务故障注入、备份下载／校验和规模边界。当前备份生成会在一个事务中读取完整小团队数据集；在 C1.6 的规模测试前，不把它描述为已验证的大数据导出器。

默认赛季修改、赛季激活、Google 双向同步、年度 Google 文件、浏览器 CORS 和 Pages 路由仍未实现。C1.5 没有配置新 secret，没有迁入真实成员或 Coach Code，也没有部署 Worker；现有生产 Apps Script、Pages API 和 Google 文件均未改变。
