# C1.2 后代码健康审查

> 状态：2026-09-21 完成。本轮只修改本地源码并提交 Git，不部署 Apps Script、Cloudflare staging 或生产环境。生产仍由 Apps Script／Google Sheets 承担业务写入，Cloudflare 仍处于隔离迁移阶段。

## 审查范围与原则

本轮检查了 Apps Script 业务与恢复层、Cloudflare Worker／Durable Object／SQLite、C1 核心和排期 API、共享运行时契约、前端 API 边界、构建脚本及现有测试。重点核对输入解析、响应投影、请求身份、幂等回放、事务、持久任务、版本字段、迁移导入和重复实现。

只改动有明确故障路径或可维护性收益的代码。`CoachModeApp.astro` 等现有大组件虽仍有拆分空间，但其异步写入、版本冲突和移动端交互已有广泛回归；在没有行为变更需求时整段重写会放大风险，因此本轮不做结构性前端迁移。Apps Script 的公开缓存空 `catch` 属于明确的降级策略：缓存失败仍返回权威数据，也不在本轮改成业务失败。

## 已修复问题

1. **幂等摘要依赖可变服务端状态**：创建训练、确认训练周和修改训练会先读取当前赛季时区，再计算请求摘要。同一已完成请求若遇到后来修改的赛季时区，可能错误返回 `IDEMPOTENCY_CONFLICT`。现在摘要只使用客户端原始字段，重放检查先于时区换算及当前图校验；核心与排期影子导入也先识别完全相同的已完成请求，再验证当前数据库图。
2. **持久任务坏数据会中断整个批次**：任务 JSON 原先在单任务错误边界之外解析，一条损坏记录可使同批后续任务全部跳过。现在每条任务在自己的 `try/catch` 内解析，并按任务类型严格验证字段；损坏任务记录错误并延后重试，同批有效任务继续完成。
3. **失败诊断不完整及零延迟热循环**：C0 模拟同步第一次失败前尚未绑定 outbox ID，因此 outbox 看不到首次失败；同时允许零毫秒重试。现在先建立诊断关联，失败立即更新 outbox 的次数和错误，并把最短重试间隔设为一秒。
4. **预约发布覆盖审计事实**：Apps Script 和 Cloudflare 都会在定时发布时覆盖管理员的确认版本、确认时间及预约开放时间。现在系统执行既有预约时只推进周版本并新增 `published_at`；原 `confirmed_version`、`confirmed_by`、`confirmed_at` 和 `scheduled_open_at` 保持不变。管理员把预约改成立即开放则明确记录一次新确认。
5. **会话载荷过度相信类型断言**：签名正确但字段形状异常的 token 可能把非法值带入数据库查询。现在对会话 ID、管理员 ID、凭据版本、签发／过期时间、后端代次和写入 epoch 做完整运行时验证，并在事务内再次核对 session 的管理员归属。
6. **C1 基础助手重复**：核心和排期服务各自实现 SQL 单行读取、契约错误转换和操作回执。现在集中到 `cloudflare/src/c1-support.ts`，减少两套实现漂移。
7. **测试夹具复用实际凭据值**：C1 测试曾使用与实际 Coach Code 相同的字符串。现行测试已改为明确的本地假值；Git 历史不会因普通提交被擦除，因此实际 Coach Code 应在下一次管理后端部署前轮换。

## 接口结论

- C1 的十九个路由、HTTP 方法、权限声明与契约清单一致，production 入口仍隐藏。
- 公开与管理投影继续分离，数据库整行不直接作为 API 响应。
- 写入的不可变操作结果与可刷新当前视图继续分离；当前视图构建失败不会把已经提交的写入报告为失败。
- 本轮没有改变现行 Apps Script 契约版本，也没有改变 C1 请求字段或成功 envelope；服务版本只用于识别以后可能部署的源码。
