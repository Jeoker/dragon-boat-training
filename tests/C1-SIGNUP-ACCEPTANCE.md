# C1.3 报名候补验收

> 状态：2026-09-21，本地实现与验证完成；未部署 staging，未连接 Pages 或 Google 业务同步，生产仍由 Apps Script／Sheets 负责。

## 实现边界

- SQLite schema v4 在 v3 之上增加报名队列序号、报名、公开限流及报名影子快照；v1–v3 数据原地保留，重复进入升级不会重复增加列。
- `shared/c1-signup-contract.ts` 定义公开与 Coach 报名、换侧、取消、当前视图和影子导入的 DTO 及严格运行时解析；[C1 接口清单](../contracts/api-cloudflare-c1.json)记录八个新增动作。
- 普通与 Coach 写入共用同一资格、容量、队列和递补实现。普通队员只能在报名截止前操作，Coach 可在训练结束前代操作；训练必须已经公开且未取消，赛季和成员必须有效。
- 固定侧和 Ambient 使用单一队列身份并按 `(queue_at, queue_sequence)` 决定先后。换侧保留原排队身份，但不会重新取得已经主动放弃且后来被占用的船位；取消后重新报名取得新的时间和序号。
- C1.3 当时只判断是否存在合法左右分配；C1.4 接入具体排座后，已有草稿或正式版时按真实空位决定可行性。Ambient 可占任一侧，每次变化后最早且可合法安置的候补先递补。
- 报名行、训练报名版本、不可变操作回执、审计及 `SIGNUP_CHANGED` outbox 在同一 SQLite 事务中提交。相同请求编号和参数只重放原结果；无变化的偏好修改保存回执，但不增加版本或 outbox。
- 公开读取返回有效成员显示名、偏好、确认／候补状态、候补位置和人数，不泄露来源键或管理字段。C1.3 当时 `seat_plan` 为空；C1.4 现已返回最新正式排座，仍不泄露私有草稿。
- `import-signups` 按稳定来源键和版本导入影子快照，验证引用、状态、队列、容量、递补完整性、时间戳及漂移。省略记录不视为删除，导入不产生 Google outbox。
- 公开写入按成员和分钟执行有界限流；不可变重放不重复计数。成员修改及核心影子导入都不能把仍有关联未来有效报名的成员改为停用。
- 排期修改预览读取真实确认／候补人数并绑定当前 `signup_version`；报名变化会使旧预览失效，为 C1.4 的排座联动保留同一版本边界。

## 本地证据

Cloudflare Workers／Durable Object 官方本地运行时验证：

- schema v3 → v4 保留核心和排期数据并创建空报名状态；未来或损坏版本继续拒绝。
- 容量满后进入候补；取消已确认报名会按原队列自动递补，当前视图和人数同步更新。
- Ambient 可在左右侧之间灵活分配，递补选择最早且仍可形成合法分配的候选人。
- 换侧保留原排队身份，但原侧已经被递补占用时不能挤回；取消后重报取得新序号，旧请求重放不改变结果。
- 两个客户端竞争最后名额时，旧版本被拒绝；刷新后可按最新状态进入候补，不发生超额。
- 普通队员到报名截止即被拒绝，Coach 在训练结束前仍可代操作，训练结束后双方都不能再改报名。
- 报名变化使既有训练修改预览失效；跨赛季成员、未发布训练和已取消训练均被拒绝。
- 直接成员修改和核心影子导入都不能绕过有效报名关联；报名影子快照的版本倒退、同版本漂移及非法队列均被拒绝。
- 公开限流达到边界后拒绝新请求；相同已完成请求的重放不占用新的限流次数。
- 影子导入不创建 Google outbox，普通与 Coach 写入按预期各创建一次待同步事件。
- 包含时区偏移的导入时间按真实时刻而非字符串排序，公开候补位置和空位递补保持一致。
- C1 当前二十七个动作的方法、业务权限和接口清单保持一致，production 入口继续固定隐藏。

验收时 Cloudflare 测试 **49／49**，其中 C1.3 专项 **13／13**；项目 Node 测试 **184／184**。Cloudflare 类型检查、类型生成和 dry-run、Astro 检查与三个页面构建、Apps Script 业务及独立桥接构建均通过。
