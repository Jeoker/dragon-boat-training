# C1.4 排座验收

> 状态：2026-09-21，本地实现与验证完成；未部署 staging，未连接 Pages 或 Google 业务同步，生产仍由 Apps Script／Sheets 负责。

## 实现边界

- SQLite schema v5 在 v4 之上增加排座状态、完整私有草稿、不可变正式 revision、revision 船位与姓名，以及排座影子快照；v1–v4 数据原地保留。
- `shared/c1-seating-contract.ts` 定义影子导入、管理工作区、保存草稿和发布正式版的 DTO 与严格运行时解析；[C1 接口清单](../contracts/api-cloudflare-c1.json)记录四个新增动作，当前共三十一个动作。
- 草稿只向有效 Coach 会话返回。公开训练只投影最新正式 revision；角色的公开投影只有显示名，管理投影另含稳定成员 ID。
- Coach 与 Steerer 可以由同一成员兼任，但角色成员不能同时报名或占用桨位。训练前只有已确认报名可以入座，发布时必须覆盖全部已确认报名；固定侧与实际船位不一致需要 Coach 明确确认。
- 保存草稿与发布分别绑定训练、报名、草稿及正式 revision 版本。业务值、不可变操作结果、审计和 `SEATING_CHANGED` outbox 在同一 SQLite 事务提交；同编号同参数重放原结果并另构建当前视图，同编号改参数拒绝。
- 取消、换侧和候补递补在报名事务内同步调整相关草稿及最新正式版，必要时创建不可变系统 revision。系统只替换与旧正式版仍一致的草稿船位，不覆盖 Coach 已经私下调整的其他布局；新确认但未能安全合并的成员明确留在待排座名单。
- 训练结束后至 `end_at + 24h` 为最终更正窗口，可用本季成员修正实际角色和船位而不改变报名；到精确截止时服务端立即拒绝保存和发布。
- `import-seating` 验证来源、完整草稿、版本单调、连续 revision、稳定 revision ID、成员引用、角色／报名冲突、船位唯一性和不可变内容。省略记录不视为删除，导入不产生 Google outbox。
- 成员停用检查已覆盖未来有效报名、私有草稿角色／船位和最新正式角色／船位；反向操作也会阻止角色成员新增报名。

## 本地证据

Cloudflare Workers／Durable Object 官方本地运行时验证：

- schema v4 → v5 保留既有数据并创建空排座状态；没有正式 revision 时公开投影为 `UNPUBLISHED`，私有空草稿只在管理工作区可见。
- 完整私有草稿不会提前公开；人工发布产生连续不可变 revision，同人兼任 Coach／Steerer 成功，公开角色不泄露成员 ID。
- 未确认队员入座、角色与报名并存、遗漏已确认队员、重复／越界船位均被拒绝；错侧发布必须显式确认。
- 已确认报名取消后，按原队列递补并在同一事务创建系统 revision；与正式版一致的草稿同步更新。
- Coach 已经调整而偏离正式版的草稿不会被系统递补覆盖；新递补成员进入待排座名单。
- 换侧保留报名时间和队列身份，但会释放不兼容的旧船位；成员不能挤回已经被占用的原侧位置。
- 最终更正不会改写报名；纯函数验证精确 24 小时边界，真实服务在边界后返回 `SEAT_PLAN_FROZEN`。
- 清空私有角色后，最新正式角色仍保护成员不能被停用；发布新 revision 清除关联后才允许停用。角色成员反向报名同样被拒绝。
- 保存结果可按原请求重放且同时返回更新后的工作区；同编号换参数返回 `IDEMPOTENCY_CONFLICT`，另起请求携带旧版本返回 `VERSION_CONFLICT`。
- 排座影子快照可幂等导入；同版本漂移、版本倒退和 revision 身份冲突被拒绝，导入不创建 `SEATING_CHANGED` outbox。

验收时 Cloudflare 测试 **59／59**，其中 C1.4 专项 **10／10**；项目 Node 测试 **184／184**。Cloudflare 类型检查、类型生成和 dry-run、Astro 检查与三个页面构建、Apps Script 业务及独立桥接构建均通过。

## 尚未完成

C1.4 已依据服务器当前时间标记 `FROZEN` 并拒绝修改，但还没有持久化训练最终姓名／座位快照，也没有建立公开历史索引。冻结状态下的当前投影仍读取最新正式 revision 和当前成员姓名，不能当作已经验收的永久年度档案。C1.5 将补齐不可变最终快照、公开历史、分页审计、受保护导出／校验快照、任务恢复和用量记录。

C1.6 的完整迁移回归和远端 staging 验收，以及默认赛季修改、赛季激活、Google 双向同步、浏览器 CORS 和 Pages 路由仍未完成。本轮只使用虚构 Coach、赛季、成员、地点和时间，没有迁入真实成员或 Code，没有配置新 secrets，也没有部署 Worker。现有生产 Apps Script、Pages API 和 Google 文件均未改变。
